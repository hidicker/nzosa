# NZOSA user acceptance tests, October 2026

Step-by-step checks for a tester working in a web browser. Each test says
what to do, and what should happen. Record each as **Pass**, **Fail** (say
what happened instead, with a screenshot) or **Blocked** (say why), in the
results table at the end.

These cover what changed between 21 and 25 October 2026: saving to books
online, and the work waiting to go live.

## Before you start

**Where to test.** The website, https://nbparagliding.nz/nzosa/, after the
changes have been deployed. Two kinds of books are used:

- **Demo books**: open the site in a **private (incognito) window** and do not
  sign in. The app fills the browser with invented books (Kea Coffee
  Roasters). Nothing here reaches anyone else; closing the private window
  throws them away. Use these for every test marked *Demo*.
- **TestOnline**: books kept online for testing. Sign in with the test account
  the owner gives you, then choose **TestOnline** on the Books page. Use these
  for every test marked *Online*. **Use no other online books.** Undo every
  change you make there (each test says how).

**Rules for the tester.**

- Do not sign in to, change or look at any books other than the demo books and
  TestOnline.
- Do not delete TestOnline or any online books.
- Where a test asks you to type a file's contents, save them as a `.csv` file
  exactly as written (plain text, one line per row).
- A step that cannot be done as written is **Blocked**, not Fail: say which
  step and what you saw.
- Window width matters for section E: use a normal desktop window (at least
  1200 pixels wide) unless a test says otherwise.

**Words used here.** The left-hand list of pages is the **menu**. A grey or
coloured box that appears over the page with buttons such as **OK** and
**Cancel** is a **dialog**. The red bar across the top of the page with a
**Reload** button is the **save banner**.

## A. Questions and messages shown on the page (Demo)

Questions that used to be the browser's own pop-up boxes now appear on the
page as dialogs, with the page dimmed behind them.

**A1. Deleting a rule asks first, and Cancel keeps it**
1. Menu → **Rules**.
2. In the rules table, press **Delete** on any rule. Note its keyword.
3. Expected: a dialog on the page reads `Delete the rule coding "<keyword>" to <account>? Confirmed lines keep their coding.` with **Cancel** and **OK**.
4. Press **Cancel**.
5. Expected: the dialog closes and the rule is still in the table.

**A2. OK deletes it**
1. Press **Delete** on the same rule, then **OK**.
2. Expected: the dialog closes and the rule is gone from the table.

**A3. Escape is Cancel**
1. Press **Delete** on another rule, then press the **Esc** key.
2. Expected: the dialog closes and the rule is still there.

**A4. A message with one button**
1. Menu → **Invoices** → **New invoice**.
2. Clear the **Invoice number** box so it is empty. Press **Save invoice**.
3. Expected: a dialog reads `Give the invoice a number.` with one button, **OK**.
4. Press **OK**. Expected: the dialog closes, and the invoice form is still open with what you typed.

**A5. A question with a box to type in**
1. Menu → **Customers & vendors** → press **Write off small balances**.
2. Expected: a dialog reads `Write off what customers still owe on an invoice when it is no more than:` with a box holding `5.00`, and **Cancel** and **OK**.
3. Replace `5.00` with `abc` and press **Enter**.
4. Expected: a second dialog reads `An amount, such as 5.00.` Press **OK**; nothing is written off.

**A6. Typing in the box, then Cancel**
1. Press **Write off small balances** again, then **Cancel**.
2. Expected: the dialog closes and nothing else happens.

## B. A bank file holding several accounts (Demo)

**B1. The Account column is found**
1. Save this as `tester-export.csv`:
   ```
   Date,Amount,Payee,Description,Reference,Account
   01/07/2025,-45.10,Woolworths,Groceries,,Everyday Account
   02/07/2025,1200.00,ACME Pty Ltd,Invoice 17,INV17,Business Cheque
   03/07/2025,-19.99,Netflix,Subscription,,Everyday Account
   ```
2. Menu → **Bank import** → **Import bank files**, and choose the file.
3. Expected: a box headed `tester-export.csv: which column is which?` shows a choice for each column. **Account, for a file of several** is set to **Account**; **Payee or other party** to **Payee**.
4. Expected: the preview table has an **Account** column showing Everyday Account, Business Cheque, Everyday Account, and the line under it says `3 lines would come in, on 2 accounts.`

**B2. Importing puts each line on its own account**
1. Press **Import with these columns**.
2. Expected: the import summary for `tester-export.csv` says `3 transactions · the columns you chose · Everyday Account, Business Cheque`.
3. Menu → **Reconcile**. Expected: the account filter at the top now includes both Everyday Account and Business Cheque.

**B3. The next file from the same bank goes straight in**
1. Save this as `tester-export-2.csv`:
   ```
   Date,Amount,Payee,Description,Reference,Account
   04/07/2025,-12.00,Cafe,Coffee,,Everyday Account
   05/07/2025,300.00,Client,Invoice 18,INV18,Business Cheque
   ```
2. Import it as in B1.
3. Expected: no "which column is which" box; the summary says `2 transactions · the columns you chose · Everyday Account, Business Cheque`.

**B4. A file naming only one account goes on the bank's own account**
1. Save B1's file again with every `Business Cheque` changed to `Everyday Account`, and with the dates changed to `06/07/2025`, `07/07/2025` and `08/07/2025` (so the lines are new). Name it `one-account.csv` and import it.
2. Expected: it goes straight in (the headings are B1's). All three lines land on **one** account: the one this layout was kept under in B1 (named after B1's file, `tester-export`), not on Everyday Account. The summary names that one account.

## C. Renaming an account carries its journals (Demo)

**C1. A journal follows its account's new name**
1. Menu → **Reports** → choose **Manual journals** in the report list → **Write a journal**.
2. Narration: `Test: reclassify an advert`. Line 1: account `Advertising` (choose it from the list), debit `100.00`. Line 2: account `Subscriptions`, credit `100.00`. Expected: the status line says `balanced`. Press **Save journal**.
3. Expected: the journal is listed, its first line naming `Advertising - 400KC` (the code may differ).
4. Menu → **Entities & accounts**. Find the Advertising row, press **Edit**, change the name to `Marketing`, press **Save**.
5. Back to **Reports** → **Manual journals**.
6. Expected: the journal's first line now reads `Marketing - 400KC`.

**C2. History says the journal moved too**
1. Menu → **History and Undo**.
2. Expected: the newest entry reads like `Advertising - 400KC renamed to Marketing - 400KC, carrying …, 1 journal line, …`.

## D. Reports by period, and beside a year earlier (Demo)

Menu → **Reports**, then choose each report from the report list. The year
list shows `FY2026 (year to 31 Mar 2026)`.

**D1. The period list**
1. Choose **Profit and loss**.
2. Expected: beside the year, a period list holds `Whole year`, `Q1 (Apr–Jun 2025)` to `Q4 (Jan–Mar 2026)`, the twelve months `April 2025` to `March 2026`, and `Choose dates…`. (`Year to date (to …)` also appears while the year is still running.)
3. Expected: a tick box `Compare with a year earlier` is beside it.

**D2. Quarters add up to the year**
1. With **Whole year**, note **Net Profit** (bottom of the table).
2. Choose Q1, Q2, Q3 and Q4 in turn, noting Net Profit each time.
3. Expected: the four add up to the whole year's figure exactly.
4. Expected: the heading names the period, e.g. `All accounts — Profit and Loss, Jan–Mar 2026 (accrual, from our own postings)`.

**D3. Months add up to the year**
1. Choose each of the twelve months, noting Net Profit.
2. Expected: the twelve add up to the whole year's figure exactly.

**D4. Chosen dates**
1. Choose `Choose dates…`.
2. Expected: two date boxes appear, starting at 1 Apr 2025 and 31 Mar 2026.
3. Set them to 1 May 2025 and 31 May 2025.
4. Expected: the heading says `May 2025` and Net Profit equals the May 2025 figure from D3.
5. Set them to 10 May 2025 and 20 Jun 2025. Expected: the heading says `10 May 2025 to 20 Jun 2025`.
6. Try to choose a date outside the year (e.g. 1 Jan 2025). Expected: the date box will not take it, or the report keeps to the year.

**D5. Compare with a year earlier: profit and loss**
1. Choose **Whole year**, tick **Compare with a year earlier**.
2. Expected: the heading ends `, beside a year earlier`. The table has columns: account, count, `FY2026`, `Apr 2024–Mar 2025`, `Change`.
3. Expected: the demo books hold no earlier year, so the year-earlier column shows `0.00` and Change equals this year's figure on each row.
4. Choose `Q2 (Jul–Sep 2025)` with the box still ticked. Expected: the columns are `Jul–Sep 2025` and `Jul–Sep 2024`.
5. Press an account name in the table. Expected: the lines behind the figure open under it, spanning the full width of the table.

**D6. The balance sheet as at a period's last day**
1. Choose **Balance sheet**, untick the compare box, and choose `Q2 (Jul–Sep 2025)`.
2. Expected: the heading says `Balance sheet as at 30 September 2025`, the last column is headed `As at 30 Sep 2025`, and the line under the heading says `Balanced. Net assets equal total equity.`
3. Choose **Whole year**. Expected: `as at 31 March 2026`.

**D7. Compare with a year earlier: balance sheet**
1. Tick **Compare with a year earlier**, with **Whole year**.
2. Expected: the heading ends `, beside 31 March 2025`; the columns are `As at 31 Mar 2026`, `As at 31 Mar 2025`, `Change`; the Opening and Movement columns are gone.
3. Untick it. Expected: the Opening and Movement columns are back.

**D8. The other reports that take a period**
For each of **Cash flow statement**, **Journal report and trial balance**,
**General ledger detail** and **Account transactions**:
1. Choose `August 2025`.
2. Expected: the heading or figures cover August 2025 only (the trial balance's heading reads `Journal and trial balance, August 2025`; the cash flow shows `Cash at 1 August 2025` and `Cash at 31 August 2025`).
3. Expected: the trial balance's debits equal its credits.

**D9. Reports that stay whole-year**
1. Choose **GST return**, then **Depreciation schedule**, then **Year-end adjustments**.
2. Expected: the period list and compare box are hidden for each.

**D10. Downloads follow the period**
1. Choose **Profit and loss**, `August 2025`, then **Download CSV**.
2. Expected: the file is named like `profit-and-loss-all-accounts-2025-08-01-to-2025-08-31.csv` and its title line names August 2025.
3. Choose **General ledger detail**, `Q1`, **Download CSV**. Expected: `general-ledger-2025-04-01-to-2025-06-30.csv`.
4. Choose **Whole year** and download again. Expected: names end `-fy2026.csv`.

## F. Reconcile on the demo books (Demo)

**F1. A tick saves and the counts move**
1. Menu → **Reconcile**. Note the line `N still to confirm. M of T coded.`
2. On a line with an account already suggested, press **✓**.
3. Expected: the line leaves the list within a second or two; the counts become N−1 and M+1.

**F2. The Undo button**
1. Press **Undo** on the row of buttons above the lines.
2. Expected: the **History and Undo** page opens, the newest entry being the tick from F1.
3. Press **Undo** on that entry. Expected: it is struck through, and back on Reconcile the line is waiting again.

**F3. Accept all says it is working**
1. On Reconcile, press **Accept all**.
2. Expected: a dialog begins `Accept N suggestions, …` and ends `They are confirmed exactly as shown. History can undo the whole batch.` Press **OK**.
3. Expected: while it runs, the button reads `Accepting N…` with moving stripes; then the list and counts update.
4. Undo the batch on **History and Undo** (one entry, `Accepted N suggestions…`). Expected: the lines are waiting again.

## G. Saving to books online (Online, TestOnline)

Sign in, open **TestOnline**, menu → **Reconcile**. Undo every change you make
here when the section is done (G7).

**G1. A tick saves**
1. Press **✓** on a line with an account suggested. Note the payee.
2. Expected: the line leaves the list; no save banner.
3. Reload the page (browser refresh). Expected: the line is still confirmed (it does not come back to the list).

**G2. Two tabs: the other-tab note**
1. Open TestOnline in a second tab (copy the address into a new tab).
2. Expected: both tabs show a note at the top: `These books are open in another tab too. Changes made in both are kept, except when both change the same line: then the second is refused. Closing one avoids that.`

**G3. Two tabs, different lines: both kept**
1. In tab 1, press **✓** on line X.
2. In tab 2 (without reloading), press **✓** on a different line Y.
3. Expected: no save banner in tab 2. Within a few seconds tab 2 no longer lists line X either (it took in tab 1's change).
4. Reload both tabs. Expected: both X and Y are confirmed.

**G4. Two tabs, the same line, the same suggestion: both kept**
1. Pick a line Z with an account suggested, showing in both tabs (reload both first).
2. Press **✓** on Z in tab 1, then **✓** on Z in tab 2 without changing anything on the line.
3. Expected: no save banner in either tab.

**G5. Two tabs, the same line, different accounts: the second refused**
1. Reload both tabs. Pick a line W showing in both.
2. In tab 1, change W's account to one account (type in its account box and choose), then **✓**.
3. In tab 2 (no reload), change W's account to a **different** account, then **✓**.
4. Expected: tab 2 shows the save banner: `These books changed somewhere else, so your last change was not saved. Reload to get the latest, then make it again.` with **Reload**.
5. Press **Reload** in tab 2. Expected: W shows tab 1's account, confirmed.

**G6. History keeps both tabs' entries**
1. Menu → **History and Undo** (either tab, after reloading).
2. Expected: an entry for each tick made in G1 to G5, newest first, none missing.

**G7. Put TestOnline back**
1. On **History and Undo**, press **Undo** on each entry made during this section, newest first. Some ticks also made a rule (`… from coding one line by hand …`): undo those too.
2. Expected: each entry is struck through; on Reconcile the lines are waiting again.
3. Close the second tab.

**G8. Books kept in the browser: the other-tab note says something else (Demo)**
1. In the private window (demo books), open the site in a second tab.
2. Expected: the note reads `These books are open in another tab too. A change made in one may be lost when the other saves: close one of them.`

## H. Online books page (Online)

**H1. Owners see Rename and Delete**
1. Menu → **Books**. In the list of books online, find TestOnline.
2. Expected: if the test account owns TestOnline, its row offers **Rename** and **Delete**; on books the account only helps with (bookkeeper, accountant or read only), neither button is shown.
3. **Do not press Delete or Rename.** If the account owns no books but TestOnline and is its owner, record what is shown and mark the "not an owner" part Blocked.

**H2. Delete asks for the name on the page (Online, optional, only with the owner's say-so)**
This deletes a set of books (an owner can restore it from the same page). Do
it only on a set of books made for the test (**Start a new set** → name it
`UAT delete test`), never on TestOnline.
1. On the `UAT delete test` row, press **Delete**.
2. Expected: a dialog on the page, `Delete "UAT delete test"? … Type the name to delete it:` with a box.
3. Type `wrong name`, **OK**. Expected: `The name did not match, so nothing was deleted.`
4. Press **Delete** again, type `UAT delete test`, **OK**. Expected: the page reloads and the set is under the deleted sets, with a way to restore it.
